# Plans

The area for breaking something big down, called **Projects** in the app (`PLANS_LABEL`): a **plan** is an ordinary page (tag `plan`, in the folder `Plans/`) whose nested list is a tree of parts. It is shown as an outline or as a map (the same list), and a part can be tied to a task and a page. The plan itself has one epic (`epicOfPlan`), where its tasks go; a part is not made into an epic (a link to an epic written before is still shown).

- The page is the data. `src/lib/planTree.ts` reads and writes only the list; the properties, the heading and every line around the list are kept as they were. A checklist line (`- [ ]`) is a task, not an idea.
- An idea is tied to something by a `[[link]]` in its line: a link to an epic page shows the epic and how far it has come; a link to another page shows the page. A link `[[note#task title]]` ties the idea to a task (any epic). A new task is added to the epic Nexmio Work makes for the plan (`epicFor`, named after the plan) and linked this way; an idea with the same words as a task of that epic shows it too. Every tie can be an existing thing or a new one. "Repeat these steps" makes one task per name in that epic, with the steps as the task's steps. The map is drawn from the top down. Nothing is copied: there is still one epic, one task, one page.
- A plan always lives in a project (a folder with its own AI rules, made with the plan or already there; a plan made before this rule can be moved into one with `MoveToProjectDialog`). `PlanProjectNotice` shows a line above a plan that is in none.
- `planHome` (in `planStore`) says, for a plan in a project, where its epics (`<project>/Epics`) and pages (`<project>/Pages`; projects made before have a `Notes` folder, which is left as it is) go; a plan that is still in no project uses `Tasks/` and the folder of the plan. "Plan from a project" only adds a plan page to the project's folder. A new page of a part is `<part>_page.md` in a folder per part above it (`partFolder`, `partPagePath`), or in another folder chosen in `NewPartPageDialog`.
- **Move to the new folder structure** (`migrate.ts`, `MigrateDialog`, `MigrateNotice`) moves the pages of parts to where a new one would go, only the ticked ones, through `vaultStore.movePages`.
- The chips on a part (`NodeChips`) mark where a linked thing is: a house in the project's folder (or the plan's own epic), an arrow (↗) outside it (`NodeInfo.outside`, `PlaceIcon`). The folder decides, not the tag; a plan in no project has no marks.
- An archived plan (shown as "Archived") has the tag `plan-finished` as well. Carrying parts over moves them to a new plan and leaves a line "Moved to [[…]]".
- The map (`mapLayout.ts`) is only a view: how each box arranges its parts (one row; a grid of N columns or N rows, one column being a stack) and which were dragged is kept per plan on this computer (`nexmio.planMap`), never in the page. A choice is found by the words of the box and those above it, without their `[[links]]` (`keyOf`), and a rename moves it (`renameKey`).
- In the app a tree item is called a "part" (not "idea"); the code keeps some old names (`addIdea`, `projectIdeas`).
- No timer, no dates. The name of the area is `PLANS_LABEL` in `planTree.ts`.
- The chosen part is shown in the right panel (the Part tab): the map draws `ChosenPart` into the box `PartSlot` makes there, because the map knows how its boxes are arranged. The map has the whole middle.
- The AI only proposes: "Suggest parts" and "Break it down" (`suggestParts.ts`) are jobs in the AI queue (`aiJobStore.addPick`), never a window that waits; the list is ticked in the Queue and only the ticked parts are written, under the part found again by its words. The AI reads the whole plan (outline with the part marked, notes, the page, pages linked to the part and above it, the plan's tasks) and is told to leave out what is elsewhere in the plan.
- A part can have a short note: indented `> ` lines right under its line (`PlanNode.note`, `setNote`, `PartNote`). Any other indented line still ends the list.
- A plan's tag is its project's tag (`planTag`; `Project.tag`, made from the name when the project is made). The plan page, its epic (`tagEpic`), tasks (`withPlanTag`) and pages made from the plan get it.
- A plan opens on the map. The right panel of the map uses the map's own actions (`mapActions`), and renames in the panel.
- An archived plan can be deleted (`planStore.remove`, `DeletePlan`): the page always, its epic and linked pages only when ticked.
- Every change goes through `usePlanStore.edit`, which reads the page again, changes its list and writes it.
- The list (`PlansPanel`) shows projects with their plan's progress (`progress.ts`). **Overview** (`ProjectOverview`, `overview.ts`) is a third view, read from the stores. **To plan…** from Ideas opens `IdeaToPlanDialog` (mounted in `App.tsx`) through `uiStore.ideaToPlan`.
